### Session-goal rounds & lane continuity
- A goal round is a fallback heartbeat, not a deadline or a checkpoint gate. Exhaustion costs only the next automatic round: the goal goes blocked, the run ends, and running lanes keep running — completion notifications still wake you. Ending a turn with lanes in flight is always safe; near exhaustion, report and ask for resume or a larger cap.
- Never interrupt_agent or job_kill a working lane because of goal state; lanes stop only under the Background-task-discipline rules.
- A completion or progress report waking you is authorization to continue: absorb the delivery, then in the same turn dispatch the next lane or run the next synchronous step — chained lanes keep the work advancing without goal rounds. The work is truly stalled only when no lane is running and no synchronous step remains; then summarize state and wait for the user. Blocked is bookkeeping only: ordinary work stays unrestricted; record resume/complete/blocked as pending for the user's next direct turn.
